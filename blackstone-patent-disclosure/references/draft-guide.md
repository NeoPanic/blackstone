# 交底书结构与交付核查

有单位或代理机构模板时按模板组织。以下结构适用于从零整理，短稿可合并相邻章节。

| 章节 | 写入内容 |
| --- | --- |
| 发明名称与技术领域 | 写技术对象和用途，如“一种用于多副本读取的索引切换方法”。 |
| 背景技术与待解决的问题 | 说明所知基线如何实现、在什么条件下出现什么可观察问题。标明基线来源。 |
| 技术方案 | 按顺序交代部件、模块或步骤及相互关系。写明输入、输出、触发条件和核心约束。 |
| 具体实施方式 | 至少完整描述一个有依据的实例。机械结构写连接、动作顺序和关键尺寸关系。工艺写材料、处理顺序、条件及控制方法。软件见[从代码到实施例](software.md)。 |
| 技术效果 | 对照基线解释哪些措施产生哪些效果，注明成立条件及验证状态。 |
| 替代实施方式 | 记录有技术依据的可选择部件、步骤或参数，以及替换时需满足的条件。 |
| 附图及说明 | 核对图中标号、名称、流程分支和正文。已有图就引用；待绘图时写明图种、图中对象和相互关系。 |
| 拟保护的技术要点 | 用具体结构或步骤概括发明人认为重要的特征组合，并关联实施例。 |
| 待确认事项 | 按影响排序，每项写明缺少的事实、对应位置和可提供的材料。 |

多个改进点共用同一机制时，可在主实施例下写各自变化。作用彼此独立时，记录各自的问题、方案和效果，便于代理师讨论如何布局。

## 交给代理师前

- 沿一个实施例从起点走到结果。检查每个关键部件或输入从哪来、如何处理、输出或状态如何被使用。遇到“自动识别”“进行优化”等省略实现的表述，指出缺的判定规则或处理步骤。
- 按技术要点回查实施例、图号和材料位置。核对正文与图中同一部件的名称、标号和连接关系。
- 按技术效果回查对应的实现条件、基线和依据。例如试验只覆盖某一种工况时，把效果限定在该工况。待补测试应说明对照方案、固定条件和观察指标。
- 对核心机制、证据或版本冲突，每个问题给一个具体补法。例如“补图 2 中密封件与阀体的接触关系，并说明压紧后密封件的变形方向”。
